# Design

## Context

图片工具已完成：`hough.py` 提供 `HoughParams`、`PRESETS`、`detect_circles`、`annotate`，`app.py` 提供 Tkinter 界面与 `--headless` 验收入口，两张实拍图的参数与结果图已固定在 README 与 `docs/`。验收依赖 Python 3.10+、OpenCV、NumPy、Pillow、Tkinter，不引入构建系统。

## Goals / Non-Goals

**Goals:**

- 视频路径与图片路径共用同一份检测核心和参数来源，结果可逐帧对照。
- 输出可复现：帧账本闭合、时间戳单调、无圆帧留空。
- 改动集中在新模块与命令行入口，图片模式与现有验收零变化。
- 为接手人留下明确的实现顺序与验收命令。

**Non-Goals:**

- 不做实时处理、跳帧或并行解码。
- 不做相机输入、多路视频、视频内目标跟踪与跨帧去重。
- 不做 GUI 视频播放器，第一版只有命令行。
- 不做 GPU 加速或编码参数调优。

## Decisions

1. **直接复用 `hough.detect_circles`。** 视频模式只负责取帧、画图与写文件，检测调用与图片模式完全相同；参数继续来自 `hough.PRESETS`。这样可以保证同一帧两种模式结果一致，也避免出现第二份算法实现。代价是无法针对视频单独调参，这属于预期范围。
2. **新增 `video.py` 承载视频 I/O。** `open_video` / `frames` / `open_writer` / 逐帧 CSV 写入集中在该模块，`app.py` 只做参数解析与调度，`hough.py` 不引入视频相关依赖。这样测试可以只解码少量帧，不必启动界面。
3. **逐帧串行处理，单线程。** 以确定性优先，第一版不跳帧、不并行；处理耗时先测量再决定是否优化，避免在没有基线的情况下引入并发复杂度。
4. **CSV 每帧一行，圆用序列化字段表达。** 列为 `frame,time_s,circle_count,circles`，`circles` 写成 `x:y:r;x:y:r` 形式的字符串，圆数量为 0 时留空。这样不受单帧圆数上限影响，也便于用 `csv` 模块稳定读写；解析规则需在 README 中写明。
5. **先写临时文件，成功后再改名。** 标注视频与 CSV 都写到同目录的临时文件，处理完成后原子替换；中途失败删除临时文件。这满足“失败不留下半成品输出”的验收要求。
6. **样例视频用确定性合成短片。** 仓库体积与素材许可都不适合直接放实拍视频；测试用脚本生成的短视频（固定尺寸、固定图案、固定帧数）作为输入，实拍视频只在本地验收时使用并在 `examples/SOURCES.md` 登记来源。

## Risks / Trade-offs

- [OpenCV 构建差异导致视频解码帧数或编码器不可用] → 验收先断言“解码帧数 = 输出帧数”，编码器不可用时给出明确错误；`mp4v` 需要在目标环境实测。
- [逐帧检测在大分辨率视频上耗时明显] → 第一版只记录处理耗时与帧率，不承诺实时；性能数据写入验收记录后再决定是否优化。
- [序列化 `circles` 字段解析成本] → 字段格式固定、圆数量单独成列，解析只做一次 `split`；若后续分析不便，可在不改动检测核心的前提下增加长表导出。
- [合成样例与实拍分布不同] → 合成短片只用于回归与帧账本校验，实拍效果以本地验收为准，并在 README 标注这一点。
